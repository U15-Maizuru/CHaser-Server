## 用語について

このマニュアルとアプリの表示は、[公式競技ルール](official/競技ルール.pdf)の用語に合わせています。
**「ゲーム」と「試合」は別の意味**なので注意してください。

| 用語 | 意味 |
|---|---|
| **ゲーム** | 1回の対戦。盤面が用意されてから決着（またはターン切れ）までの1本 |
| **試合** | 同じマップで先攻・後攻を入れ替えた**2ゲーム**のまとまり。勝者は 勝利数 → 合計ポイント の順で決まる |

アプリの **[2ゲーム制]** を ON にすると、公式ルールどおり「1試合 = 2ゲーム」で進行します。
OFF のときは1ゲームだけを行い、そのゲームの結果がそのまま試合の結果になります。

詳しくは [13. 公式競技ルールとの対応](#13-公式競技ルールとの対応) を参照してください。

## 1. 動作モードの選択

このアプリには **2つの動作モード** があります。目的に応じて使い分けてください。

| モード | 使い方 | 向いている場面 |
|---|---|---|
| **ローカルモード** | Electron アプリを起動する | 1対戦のみ・スタンドアロン利用 |
| **Web サービスモード** | Node.js をサーバーとして起動する | 複数ペアが同時に対戦する大会 |

**どちらのモードでも Python AI プログラムは同じコードを使えます。** 接続先のホストとポート番号だけが異なります。

## 2. ローカルモード — Electron アプリ

### 起動方法

インストーラーから実行する場合はアイコンをダブルクリックするだけで起動します。

開発モードで起動する場合:
```bash
pnpm --filter @u15/electron dev
```

### 2ウィンドウ構成

アプリ起動時に**2つのウィンドウ**が自動的に開きます。

```
┌──────────────────────────────────┐   ┌──────────────────────────────────┐
│   対戦表示ウィンドウ              │   │  コントロールウィンドウ           │
│   (1280×800)                     │   │  (1280×800)                      │
│                                  │   │                                  │
│   [常時ゲームボードを表示]        │   │  [プレイヤー設定]                    │
│   プロジェクターや観客用          │   │  [ゲーム操作]                    │
│   モニターに映す                  │   │  [設定変更]                      │
│                                  │   │                                  │
└──────────────────────────────────┘   └──────────────────────────────────┘
```

| ウィンドウ | 役割 |
|---|---|
| **対戦表示ウィンドウ** | ゲームボードを常時表示。セットアップ中は「対戦開始をお待ちください」と両プレイヤーの接続状態を表示。メニューバーは非表示 |
| **コントロールウィンドウ** | プレイヤー設定・プログラムアップロード・ゲーム開始など全操作はここで行う |

このほか、スロットを「手動操作」にすると **手動操作ウィンドウ** (360×560) が COOL / HOT ごとに開きます（9章参照）。

各ウィンドウのタイトルバーには「対戦表示 — CHaser Server」のように役割が先に出ます。タスクバーでウィンドウを選ぶときの目印にしてください（大会運営ウィンドウは「大会運営 — CHaser Server」、手動操作は COOL / HOT まで出ます）。

> **運営のヒント**: 対戦表示ウィンドウをプロジェクターに映し、コントロールウィンドウで操作すると、観客に見やすい進行ができます。コントロールウィンドウを閉じるとアプリ全体が終了します。

### 全画面表示と、その解除

コントロールウィンドウのフッターの **[⛶]** で、対戦表示ウィンドウを全画面にできます。プロジェクターに映すときはこれを使ってください。

全画面にすると、対戦表示ウィンドウが画面全体を覆い、コントロールウィンドウの [⛶] は裏に隠れます。**解除は対戦表示ウィンドウで `ESC` キー**を押してください。`F11` でも全画面の入り切りができます（どちらも対戦表示ウィンドウを選択した状態で押します）。

### AI プログラムの接続先 (ローカルモード)

起動ログに表示されるIPとポートを参加者に伝えてください。

```
COOL AI 接続先: 192.168.1.9:2009
HOT  AI 接続先: 192.168.1.9:2010
```

## 3. Web サービスモード — ブラウザロビー

複数ペアが同時に個別の対戦を行う場合に使います。

### サーバー起動

```bash
# ビルド (初回のみ)
pnpm build

# サーバー起動
NODE_ENV=production U15_MODE=web PORT=8765 node apps/backend/dist/index.js
```

### ロビー画面

参加者はブラウザで `http://サーバーIP:8765/` を開くとロビーが表示されます。

```
┌────────────────────────────────────────┐
│  CHaser Server  ロビー            │
│                                        │
│  [+ 新しいルームを作成]                │
│                                        │
│  ┌──────────────────────────────────┐  │
│  │ セットアップ中  Room a1b2c3...   │  │
│  │ COOL: 13042   HOT: 13043        │  │
│  │                          [観戦] │  │
│  └──────────────────────────────────┘  │
└────────────────────────────────────────┘
```

### ルームの作成と参加

1. **ルーム作成者（運営）**: 「新しいルームを作成」をクリック → コントロール画面が開く
2. **AIプログラム担当者**: 表示された TCP ポートに AI を接続する
3. **観戦者**: ロビーで「観戦」をクリック、または URL を共有する

### URL の種類 (Web サービスモード)

| URL | 内容 |
|---|---|
| `http://サーバーIP:8765/` | ロビー（ルーム一覧） |
| `http://サーバーIP:8765/?room=<id>&mode=control` | 特定ルームの操作画面 |
| `http://サーバーIP:8765/?room=<id>&mode=display` | 特定ルームの観戦画面 |
| `http://サーバーIP:8765/?room=<id>` | 観戦画面（デフォルト） |

### ファイアウォールの設定 (Web サービスモード)

```
TCP inbound: 8765       (Web / WebSocket / ファイルアップロード)
TCP inbound: 13000-14999 (AI プログラム用、動的割り当て)
```

## 4. コントロール画面 — セットアップ

コントロール画面には以下のレイアウトが表示されます。

```
┌────────────────────────────────────────────────────────────┐
│  CHaser Server  セットアップ  IP: 192.168.1.9         │
├─────────────────────┬─────────────┬────────────────────────┤
│  COOL (青パネル)    │   マップ     │  HOT (赤パネル)        │
│                     │ ┌─────────┐ │                        │
│ [プログラム][TCP]   │ │         │ │ [プログラム][TCP]      │
│ [CPU][手動操作]     │ │ プレビュー│ │ [CPU][手動操作]        │
│                     │ │         │ │                        │
│ プログラム未選択    │ └─────────┘ │ プログラム未選択       │
│           [変更▾]  │ ランダム生成 │            [変更▾]    │
│                     │ 15×17       │                        │
│ カスタムライブラリ ▼│ ターン100    │ カスタムライブラリ ▼   │
│                     │ [変更▾]     │                        │
├─────────────────────┴─────────────┴────────────────────────┤
│ [マップ管理...][プログラム管理...] ゲームスタート           │
│                              [設定][⛶][リセット]● CONNECTED│
└────────────────────────────────────────────────────────────┘
```

- **左パネル (COOL)** / **右パネル (HOT)**: 各プレイヤーの設定
- **中央のマップ列**: 現在のマップのプレビューと要約、および「対戦で使うマップ」の選択（「変更 ▾」）
- **対戦ルール・進行の設定**: フッターの[設定]→「対戦」タブにまとまっています
- **フッター**: 3つの役割に分かれています
  - **左**: ライブラリの管理 (マップ管理・プログラム管理) — セットアップ中のみ表示
  - **中央**: 「次の一手」 — 状況に応じて1つだけ表示 (ゲームスタート / 第2ゲームへ / もう一度対戦 / セットアップに戻る)
  - **右**: いつでも使えるもの (設定・全画面化・リセット・接続状態)
- **ローカル IP**: 対戦表示ウィンドウの待機画面にも表示されます

> **リセットはいつでも押せます**: 対戦中は「中断」、それ以外は「リセット」と表示され、デモモードの自動進行やリピートモードの再戦ループから抜けたいときの出口になります。

## 5. プログラムの用意と割り当て

プログラムは「**ライブラリに登録する**」と「**プレイヤーに割り当てる**」の2段階に分かれています。ライブラリは全ルーム共通で、一度登録すれば何度でも使い回せます。

### 5-1. ライブラリに登録する（プログラム管理）

1. フッターの「プログラム管理...」を押します（セットアップ中のみ表示）
2. ダイアログ下部のドロップエリアに `.py` / `.exe` ファイルをドラッグ＆ドロップします（クリックしてファイル選択も可）
3. アップロード中はプログレスバーが表示されます
4. 一覧に追加されます。ここでは削除と「デモ対象」の切り替えもできます

> アップロードしただけでは対戦には使われません。次の 5-2 でプレイヤーに割り当ててください。

### 5-2. プレイヤーに割り当てる

1. プレイヤーパネルのモードが「プログラム」になっていることを確認します
2. 「プログラム未選択」と書かれた欄の「変更 ▾」を押します
3. 一覧から使いたいプログラムの「使用」を押します
4. 同じ操作を COOL と HOT の両方で行います

選択を取り消すときは「選択を解除」を押します。

### 5-3. モードの切り替え

| モード | 用途 |
|---|---|
| **プログラム** | Pythonファイルをアップロードして実行（通常の対戦） |
| **TCP接続** | 外部PCからTCPで接続（IPとポートで接続する場合） |
| **CPU** | 内蔵AIで動作（テスト・動作確認用） |
| **手動操作** | キーボードで人間がプレイ（デモ用） |

### 5-4. カスタムライブラリの追加

「カスタムライブラリ ▼」をクリックして展開すると、pychaser 以外のライブラリを追加できます。

- **pychaser** はシステムにプリインストール済みです。アップロード不要です
- 追加ライブラリは `.py` ファイル単体のみ対応します
- プレイヤーごとに別々のライブラリを設定できます

## 6. マップの設定

マップもプログラムと同じく「**ライブラリに登録する**」と「**対戦で使う**」の2段階に分かれています。ライブラリは全ルーム共通で、一度登録すれば何度でも使い回せます。**アップロードしただけでは対戦には使われません。**

セットアップ画面の中央（COOL と HOT の間）のマップ列に、現在のマップのプレビューとサイズ・ターン数・ブロック数・アイテム数、そして選択中のマップ名が表示されます。ここの「変更 ▾」から使うマップを選びます。

> **2ゲーム制の第2ゲーム待機中はマップを変更できません。** 1つの試合内で両ゲームが同じマップを使うためです。このときは「変更 ▾」が押せなくなり、セットアップ画面には「マップと対戦ルールは第1ゲームと共通です」と表示されます（プレビューとマップ管理はそのまま使えます）。

### 6-1. ライブラリに登録する（マップ管理）

1. フッターの「マップ管理...」を押します（セットアップ中のみ表示）
2. ダイアログ下部のドロップエリアに `.map` ファイルをドラッグ＆ドロップします（クリックしてファイル選択も可）
3. 一覧に追加されます。ここでは名前での検索・「DL」でのダウンロード・「削除」ができます

ここでは対戦で使うマップの選択は行いません。選択は次の 6-2 で行います。

### 6-2. 対戦で使うマップを選ぶ

マップ列の「変更 ▾」を押すと、3つのソースから選べます。

| タブ | 内容 |
|---|---|
| **ライブラリ** | アップロード済み・保存済みのマップから選ぶ。名前で検索し「使用」を押す |
| **ランダム** | パラメータを指定してその場で生成する |
| **エディタ** | マップエディタで作る |

選んだマップは「リセット」や「もう一度対戦」をしても保たれます（ランダムのみ、後述のとおり毎回引き直されます）。

#### ランダム生成のパラメータ

| 設定 | 初期値 | 説明 |
|---|---|---|
| フィールドサイズ | 決戦 (15×17) | 決戦 (15×17) / 広域 (21×17) から選択。**公式ルールのサイズは 15×17** |
| ターン数 | 100 | 最大ターン数。**公式ルールは 100〜240** |
| ブロック数 | 20 | 配置する岩の数（偶数推奨） |
| アイテム数 | 51 | 配置するアイテム数（奇数推奨） |
| 対称配置 | ON | 左右対称で生成する |

「生成して使用」を押すとその場でランダムマップを生成し、今のゲームに適用します。

> **この設定はサーバーが記憶します。** アプリ起動直後の初期マップにも使われ、「リセット」や「もう一度対戦」のたびにこの設定で**新しいマップが引き直されます**。同じ盤面を使い続けたいときは、次の 6-3 でライブラリに保存してから「ライブラリ」タブで選び直してください。

### 6-3. ランダム生成・エディタのマップを残す

ランダム生成またはエディタで作ったマップを選んでいるときは、マップ列の選択パネルの下部に「今のマップを残す」欄が出ます。

1. 名前を入力します（初期値として `map-MMDD-HHmm` が入っています）
2. 「ライブラリに保存」でサーバー内のマップライブラリに保存します
3. 「ダウンロード」で `.map` ファイルとして手元に保存します

保存しても対戦で使うマップの選択は切り替わりません（ランダムのままなので、リセットすると引き直されます）。保存したマップを固定して使いたいときは「ライブラリ」タブから選び直してください。

### 6-4. マップエディタで作成・編集

「エディタ」タブの「エディタで編集...」を押すと、現在のマップを初期状態として Canvas ベースのエディタが開きます（新規作成ではなく、今のマップをそのまま編集できます）。

| ツール | 操作 |
|---|---|
| **消しゴム** | マスを空白にする |
| **ブロック** | 岩（ブロック）を配置する |
| **アイテム** | アイテムを配置する |
| **開始位置** | プレイヤーの初期位置を設定する |

- 「ランダム生成」ボタンでフィールドサイズに応じたマップを自動生成します（6-2 のパラメータを使います）
- 「適用して閉じる」で編集内容を今のゲームに反映して閉じます。適用したマップはリセットしても残ります
- 「マップ名」を入力して「ライブラリに保存」でマップライブラリに保存します（今のゲームには反映されません）
- 同じく「ダウンロード」で `.map` ファイルとしてダウンロードします（ライブラリには保存されません）

## 7. ゲームの開始と対戦表示

### 7-1. ゲーム開始

COOL と HOT の両方が **「準備完了」** になると、フッターの「ゲームスタート」ボタンが有効になります。

### 7-2. 対戦表示画面の見方

左右のサイドパネルは、**その側のプログラム自身**の成績を表示します（左パネル = 画面左のプログラム、
右パネル = 画面右のプログラム）。画面の左右は対戦を通じて同じプログラムに固定されます。

**1ゲーム制（デフォルト）**

```
┌────────────────────────────────────────────────────────────┐
│  [COOL名] [COOL得点 | 残りアイテム | HOT得点] [HOT名]      │ ← 上部バー
├──────────────┬────────────────────────────┬────────────────┤
│  ┌─────────┐ │       ゲームボード          │ ┌──────────┐   │
│  │  COOL   │ │  (プレイヤーがターンごとに   │ │   HOT    │   │
│  │アイテム  │ │   動き、1ターン経過後に      │ │アイテム   │   │
│  │一撃     │ │   次のターンへ進む)          │ │一撃      │   │
│  │総取り    │ │                             │ │総取り     │   │
│  ├─────────┤ │                             │ ├──────────┤   │
│  │合計 　   │ │                             │ │合計　     │   │
│  │ ポイント │ │                             │ │ ポイント  │   │
│  └─────────┘ │                             │ └──────────┘   │
├──────────────┴────────────────────────────┴────────────────┤
│         [残りターン数ゲージ] → 終了後は勝敗を表示           │ ← 下部バー
└────────────────────────────────────────────────────────────┘
```

- 「一撃」「総取り」は決着してから確定するため、ゲーム中は「—」と表示されます
- 「アイテム」と「合計ポイント」はゲーム中も「獲得アイテム数×10」でリアルタイムに増え、決着時にボーナスが加算されます

**2ゲーム制**

各パネルが第1ゲーム・第2ゲームの明細（アイテム・一撃・総取り・小計）になり、その下の「総合」が
その側の2ゲームの成績になります。2ゲームの「小計」を足したものが「総合」の「合計」です。
第2ゲームは先攻・後攻が入れ替わるため、同じパネルの中で COOL / HOT のラベルが入れ替わります。

```
     左パネル                              右パネル
┌──────────────────┐                ┌──────────────────┐
│第1ゲーム COOL WIN│                │第1ゲーム HOT LOSE│
│ アイテム     40pt│                │ アイテム     30pt│
│ 一撃        +50pt│                │ 一撃         −9pt│
│ 総取り      +18pt│                │ 総取り        0pt│
│ ──────────────── │                │ ──────────────── │
│ 小計        108pt│                │ 小計         21pt│
├──────────────────┤                ├──────────────────┤
│第2ゲーム HOT  WIN│ ← 先攻・後攻が │第2ゲーム COOL LOSE│
│   （同じ明細）   │    入れ替わる  │   （同じ明細）   │
├──────────────────┤                ├──────────────────┤
│🏆 総合           │                │⭐ 総合           │
│      2勝0敗      │ ← 勝者を決める①│      0勝2敗      │
│ 合計       216pt │ ← 同数なら②   │ 合計        42pt │
└──────────────────┘                └──────────────────┘
```

| 表示 | 意味 |
|---|---|
| 上部バー | 左プレイヤー名・得点 \| 盤面に残っているアイテム数 \| 右プレイヤー名・得点 |
| 下部バー（ゲーム中） | 残りターン数のゲージ |
| 下部バー（終了後） | **そのゲームの**勝者と決着理由（2ゲーム制の第2ゲーム終了時も同じ） |
| 「総合」欄の 🏆（2ゲーム制のみ） | 試合全体の勝者に付きます（**勝利数**が多い方。同数なら**合計ポイント**） |
| 「総合」欄の「◯勝◯敗」（2ゲーム制のみ） | 勝者を決める第1基準。これで決まったときは緑の枠が付きます |
| 「総合」欄の「合計」（2ゲーム制のみ） | 勝者を決める第2基準（勝利数が並んだとき）。これで決まったときは緑の枠が付きます |
| 各パネルの「アイテム」 | そのゲームで獲得したアイテムのポイント = アイテム数 × 10（個数ではありません） |
| 各パネルの「一撃」 | アタック・閉じ込めで**勝った**側に **+50**／衝突・自縛・通信エラーで**負けた**側に **−3 × 自分のアイテム数** |
| 各パネルの「総取り」 | 勝者へのボーナス = **6 ×** 決着時点で盤面に残っていたアイテム数 |
| 各パネルの「小計」（2ゲーム制のみ） | そのゲームの アイテム + 一撃 + 総取り |
| 各パネルの「合計ポイント」 | 獲得アイテム数×10 + 一撃 + 総取り（2ゲーム制では2ゲームの合算） |

### 7-3. 1ターンの表示時間

デフォルトでは **1ターンごとに0.5秒間** ボードが表示されてから次のターンに進みます。フッターの[設定]→「対戦」タブ→「進行」で変更できます（進行中のゲームには影響せず、次のゲームから反映されます）。

### 7-4. ゲーム終了

ゲームが終了すると下部バーに結果（勝者と決着理由 / 引き分け）が表示されます。コントロール画面の「セットアップに戻る」ボタンでリセットできます。

#### 盤面上の決着演出

決着した瞬間、**盤面上でも勝敗が分かるようになります**。文字を読まなくても、どちらが勝ったか・何が起きたかが伝わります。表示は次のゲームが始まる（またはリセットする）まで残ります。

**まず、どの決着理由でも共通で:**

| 誰 | 盤面の見え方 |
|---|---|
| 👑 **勝ったロボット** | **金色の光に包まれ**、👑 が付きます |
| **負けたロボット** | **暗く沈みます** |
| 🤝 **引き分け**（アイテム数が同じとき） | **両方**のロボットが金色の光に包まれ、🤝 が付きます |

**そのうえで、負けたロボットには「なぜ負けたか」が表示されます:**

| 決着理由 | 負けた側の見え方 | 枠の色 |
|---|---|---|
| 💥 アタック | **上にブロックが乗る**（下敷き） | **相手プレイヤーの色**（🔵 青 / 🔴 赤）＝ 相手に潰された |
| 💫 衝突 | **上にブロックが乗る**（下敷き） | **オレンジ**＝ 自分からブロックに突っ込んだ |
| 🚧 閉じ込め | **上下左右のブロックが光る** | **相手プレイヤーの色**＝ 相手に囲まれた |
| 🔒 自縛 | **上下左右のブロックが光る** | **オレンジ**＝ 自分で自分を囲んでしまった |
| 📵 通信エラー | 枠とバッジのみ | **オレンジ**＝ 自分の側の通信が切れた |
| 🎯 アイテム数（タイムアップ） | 暗く沈むだけ（枠もバッジも無し） | — |

**枠の色が「誰のせいか」**（相手プレイヤーの色なら相手に仕掛けられた／オレンジなら自滅）、**バッジの絵柄が「何が起きたか」**を表します。オレンジ＝自滅は「一撃」の罰点（−3 × 自分のアイテム数）が付く決着理由と一致します。

タイムアップ（アイテム数で決着）のときは負けた理由というものが無いため、勝者の 👑 と敗者の暗転だけで勝敗を示します。

> 勝者の**金色は「光の面」**、自滅のオレンジは**「線の枠」**として描き分けているので、色が似ていても取り違えることはありません。

下部バーが示すのは、2ゲーム制であっても**直前のゲームの勝敗**です。試合全体の最終勝者は「勝利数が多い方、同数なら2ゲームの合計ポイント」で決まるため、勝者側パネルの「総合」欄に 🏆 と枠が付く形で示されます。1勝1敗になったときは、第2ゲームを落としていても第1ゲームの点差で合計が上回っていれば 🏆 が付くのはそちらの側になります。

## 8. 2ゲーム制モード

同じマップで先攻・後攻を入れ替えた2ゲームを行い、**勝利数が多い方**を勝者とします。
勝利数が同じ（1勝1敗など）の場合は、**2ゲームの合計ポイント**で決まります。

### 有効化方法

フッターの[設定]→「対戦」タブ→「対戦ルール」で **[2ゲーム制]** を押します。押した時点で反映され、チップに ✓ が付きます（[保存] は不要です）。

### 2ゲーム制フロー

```
[第1ゲーム: COOL先攻・HOT後攻]
      ↓ ゲーム終了
  「第2ゲームへ」ボタン表示 → クリック
      ↓
  COOLとHOTのプログラムが自動入れ替え
      ↓
  表示画面は待機画面に戻り、第1ゲームの結果
  (両者の合計ポイント) を出したまま接続を待つ
      ↓
[第2ゲーム: COOL後攻・HOT先攻]
      ↓ ゲーム終了
  勝利数 (同数なら合計ポイント) で最終勝者決定
  勝者側パネルの「総合」に 🏆 が付き、
  決め手になった方 (勝敗数 / 合計) に緑の枠が付く
  (下部バーは第2ゲームそのものの勝敗を表示)
```

表示画面の左右の位置は2ゲームを通じて同じプログラムに固定されます（待機画面のプレイヤーカードも同じ並びです）。
先攻・後攻が入れ替わるため、カードの COOL / HOT のラベルと色は第2ゲームで左右が入れ替わります。

## 9. 手動操作モード

1. プレイヤーパネルで「手動操作」を選択する
2. 相手プレイヤーを CPU または TCP に設定する
3. 「ゲームスタート」を押す

操作は COOL/HOT それぞれ専用の**手動操作ウィンドウ**（矢印キーとボタンで操作するパネル）で行います。

- **ローカルモード (Electron アプリ)**: スロットを「手動操作」に設定すると、専用ウィンドウが自動的に開きます
- **Web サービスモード**: 自動では開かないため、操作担当者に `http://サーバーIP:8765/?room=<id>&mode=manual&slot=0` (COOL) または `&slot=1` (HOT) の URL を共有してください

| アクション | 動作 |
|---|---|
| **WALK** | 方向に1マス移動（アイテムがあれば取得） |
| **LOOK** | 指定方向の**2マス先を中心とする3×3**（＝その方向の1〜3マス先）を調べる。移動なし |
| **SEARCH** | 指定方向の**まっすぐ9マス**（1〜9マス先）を調べる。移動なし |
| **PUT** | 方向にブロックを設置 |

調べた9マスには、床・ブロック・アイテムに加えて**相手プレイヤーの位置**も含まれます。
LOOK / SEARCH は「相手がどこにいるか」を離れた場所から探すための行動です。
（Python ライブラリでは `Enemy` として返ります。`get_ready()` や `walk()` の周囲9マスでも同様です）

LOOK / SEARCH を実行すると、**盤面上に調べた範囲がプレイヤーカラー（COOL=青 / HOT=赤）で表示されます**。
自分のいる側から順に光が走るので、どちらの方向を調べたのかが一目で分かります。
観戦画面とメイン操作画面の両方に出るため、どちらのプレイヤーがどこを調べたかを観客が追えます。
ダークモード中も、調べた範囲だけは一時的に見えるようになります。

### 10-1. 設定ダイアログ（フッターの[設定]）

**表示タブ**

| 設定 | デフォルト | 説明 |
|---|---|---|
| 観戦画面のタイトル | CHaser Server | 観戦画面・コントロール画面の見出しに使われます |
| テクスチャテーマ | Jewel | Jewel / Light / Heavy / RPG から選択 |
| SE ミュート | OFF | 効果音をオフにする |
| ダークモード (視界のみ表示) | OFF | 各プレイヤーの視界(周囲9マス)以外を幕で覆って表示する。**チェックした瞬間に反映されます**（対戦中でも切り替え可） |
| ダーク幕の濃さ | 55% | ダークモードで盤面を覆う幕の濃さ。**動かした瞬間に反映されます**（観戦画面も同時に変わります）。会場が明るくて幕が薄く見えるときは濃く、プロジェクタが暗くて盤面の形が読めないときは薄くしてください |

**対戦タブ**

| 設定 | デフォルト | 説明 |
|---|---|---|
| 2ゲーム制 | OFF | 先後を入れ替えた2ゲームを行い、合計得点で勝者を決める |
| リピート | OFF | 最終ゲーム終了後、両プレイヤーの接続を維持したまま先後を入れ替えて再戦できるようにする |
| デモ | OFF | 準備が整うと自動的に開始し、第2ゲーム・再戦も自動で進む（無人展示向け） |
| ターン表示 | 0.5秒 | ターンごとにボードを表示する時間（0 = 即時） |
| TCPタイムアウト | 10秒 | クライアントの応答待ち時間 |

このタブの項目は **[保存] を待たず、操作した時点で反映されます**。

対戦ルール（2ゲーム制・リピート・デモ）はセットアップ中しか変更できません。対戦中や、2ゲーム制で試合の途中（第2ゲーム待ち）のときはチップが無効表示になり、理由が表示されます。進行（ターン表示・TCPタイムアウト）はいつでも変更でき、進行中のゲームには影響せず次のゲームから反映されます。

> **デモを ON にすると、両プレイヤーのプログラムがライブラリの「デモ対象」からランダムに選び直されます。** 手動で選んでいた場合は上書きされるため、確認メッセージが出ます。
>
> **デモを止めたいときは、フッター右の「リセット」を押してください。** 自動進行が止まり、セットアップ画面に戻ります。

> **ターン表示時間**: 0に設定するとゲームが一瞬で終了します。観客向けには1〜2秒を推奨します。

**BGM タブ**

対戦中に再生する BGM を選択・アップロード（mp3/wav）・ミュートできます。

**環境タブ (ローカルモードのみ)**

Electron アプリから起動している場合にのみ表示されます。ログの保存先フォルダや、対戦プログラム
実行に使う Python コマンドを上書きできます。Web サービスモードでは、リモートのクライアントが
サーバー上の任意パスへの書き込みや任意コマンドの実行経路に触れないよう、この設定は無視されます。

## 11. Python AI プログラムの接続

### 同じプログラムをどちらのモードでも使える

Python AI プログラム自体は **ローカルモードでも Web サービスモードでもそのまま動作します**。接続先のホストとポート番号だけを変えるだけです。

```bash
# ローカルモード (ポートは固定)
python player.py --host 192.168.x.x --port 2009    # COOL
python player.py --host 192.168.x.x --port 2010    # HOT

# Web サービスモード (ポートはロビーまたはコントロール画面に表示される値)
python player.py --host example.com --port 13042   # COOL
python player.py --host example.com --port 13043   # HOT
```

### 接続先ポートの確認

| モード | ポートの確認方法 |
|---|---|
| ローカル | 起動ログまたは対戦表示ウィンドウの待機画面 |
| Web サービス | ロビーのルームカード、またはコントロール画面のヘッダー |

### TCP プロトコル (参考)

```
client → server: "[プレイヤー名]\r\n"     (接続後最初の送信)

1ターン = 3フェーズ:
  server → "@ \r\n"                  (GetReady)
  client → "gr\r\n"

  server → "[ConnectStatus][9マスの状態]\r\n"  (周囲情報)
  client → "[action][rote]\r\n"      例: "wr\r\n" (WALK RIGHT)

  server → "[更新後の周囲情報]\r\n"
  client → "#\r\n"                   (EndSharp)
```

## 12. エラーと対処法

### 「プログラムの起動に失敗」

- 配布版アプリ（インストーラーで導入した場合）は Python 実行環境を同梱しているため、「プログラム」モードでのアップロード実行に別途 Python のインストールは不要です
- 開発環境で動かしている場合、または「TCP接続」モードで手元の Python から接続する場合は、Python がインストールされ PATH が通っているか確認してください
- ファイルパスに日本語や特殊文字が含まれていないか確認してください
- `.py` ファイルが正しい pychaser プログラムか確認してください

### ポート使用中エラー

- 別のサーバーが起動していないか確認してください
- アプリを完全に終了してから再起動してください

### 「TCP接続待ち」のまま変わらない

- AI プログラムが指定ポートに接続しているか確認してください
- ファイアウォールでポートがブロックされていないか確認してください
- Web サービスモードの場合、ロビーに表示されている動的ポートに接続しているか確認してください

### ロビーにルームが表示されない (Web サービスモード)

- `U15_MODE=web` でサーバーが起動しているか確認してください
- ブラウザのキャッシュをクリアして再接続してください
- WebSocket が接続されていれば数秒でルーム一覧が表示されます

### ゲームが表示されないまま終わる

- フッターの[設定]→「対戦」タブ→「進行」で「ターン表示」が 0 秒になっていると一瞬で終了します
- 0.5秒以上に設定してから再試行してください

### 全画面のまま戻せない

- 全画面のウィンドウを選んだ状態で `ESC` を押すと解除されます（`F11` でも入り切りできます）
- コントロールウィンドウが裏に隠れているときは `Alt` + `Tab` で選び直せます

## 13. 公式競技ルールとの対応

原典は [docs/official/競技ルール.pdf](official/競技ルール.pdf) です。ここでは、大会運営で
アプリを設定するときに関係する項目だけを対応表にまとめます。

### 13-1. 勝利条件と画面上の表示

| 公式ルールの勝利条件 | 画面の決着理由 | 盤面のバッジ |
|---|---|---|
| 規定ターン終了時にアイテム数が多い | アイテム数 | （なし。勝者の 👑 と敗者の暗転のみ） |
| 相手がブロックのあるマスに移動する（衝突） | 衝突 | 💫 |
| 相手がいるマスにブロックを置く（アタック） | アタック | 💥 |
| 相手が上下左右4方向をブロックで囲まれる（閉じ込め） | 閉じ込め | 🚧 |
| 自分でブロックに囲まれたとき（自縛） | 自縛 | 🔒 |
| 相手が通信エラーなどで競技を中断させる（中断） | **通信エラー** | 📵 |

> 公式ルールで「中断」と呼ぶ決着は、アプリでは **「通信エラー」** と表示します。フッターの
> リセットボタンが対戦中に「中断」と出る（＝運営が対戦を打ち切る操作）ため、区別できるよう
> 言葉を分けています。得点上の扱いは公式どおり「中断【敗】」と同じです。

### 13-2. 獲得ポイント

| 公式ルール | アプリのサイドパネル |
|---|---|
| Ⅰ. アイテム【両】: 獲得したアイテム数×10 点 | 「アイテム」 |
| Ⅱ. 一撃ボーナス（ペナルティ）: アタック・閉じ込め【勝】+50 点 / 衝突・自縛・中断【敗】獲得したアイテム数×3 点を減点 | 「一撃」 |
| Ⅲ. 総取り【勝】: 残りのアイテム数×6 点を加点 | 「総取り」 |

1ゲームぶんの合計が「小計」、2ゲーム分の合計が「総合」欄の「合計」です。

### 13-3. 先攻・後攻の割り当て

公式ルールでは、**第1ゲームは組み合わせ表の選手番号が小さい選手が先攻**、大きい選手が後攻です。
アプリでは **COOL スロットが第1ゲームの先攻**（画面左・青）、HOT スロットが後攻（画面右・赤）に
なります。運営は選手番号の小さい方のプログラムを COOL に割り当ててください。第2ゲームでは
アプリが自動で先攻・後攻を入れ替えます。

また公式ルールでは、**プログラムは提出後に試合・ゲームごとに差し替えられません**。第2ゲームへ
進むときにプログラムを選び直す必要はなく（アプリが同じプログラムのまま先後だけ入れ替えます）、
選び直しは規定違反になります。

### 13-4. 試合における勝敗

公式ルールでは **① 勝利数 → ② 2ゲームの合計ポイント** の順に試合の勝者を決めます。アプリでは
勝者側パネルの「総合」欄に 🏆 が付き、決め手になった行（「◯勝◯敗」または「合計」）が緑の枠で
強調されます。

> **勝利数・合計ポイントとも同点の場合、公式ルールでは「マップを変更して再試合」です。**
> このときアプリはどちらにも 🏆 を付けません（自動で再試合は始まりません）。運営が
> 「リセット」→マップを選び直して、もう一度試合を行ってください。

### 13-5. マップとターン数

| 項目 | 公式ルール | アプリの既定値・設定範囲 |
|---|---|---|
| マップサイズ | 横 15・縦 17 | ランダム生成の「決戦 (15×17)」が公式サイズ。「広域 (21×17)」は練習・デモ用の公式外サイズ |
| ターン数 | 1ゲーム 100 以上 240 以下 | 既定 100。ランダム生成・マップエディタで変更可（範囲外の値も設定できるため、本番前に確認してください） |
| プレイヤー初期位置 | マップ中央より左に先攻、右に後攻 | ランダム生成は先攻 (COOL) を必ず盤面左側に置き、「対称配置」ON なら後攻を点対称の位置に置きます。`.map` ファイルは `C:` / `H:` 行の座標に従うため、自作マップでは左右を自分で守ってください |

### 13-6. 競技方法（トーナメント / リーグ）

1試合ずつ手で回す使い方（1〜12章）では、トーナメントの組み合わせや総当たり戦の勝ち点
（勝利3点・引き分け1点・敗北0点）による順位決定はアプリの管轄外です。アプリは1試合ぶんの
進行と得点表示のみを担当するため、順位表は運営側で集計してください。

**[14. 大会を運営する](#14-大会を運営する) を使う場合は、これらもアプリが担当します。**
選べる競技方法は4つです。

| 競技方法 | 順位の決め方 |
|---|---|
| トーナメント（勝ち上がり） | 勝ち抜き |
| リーグ（総当たり） | 勝ち点 → 合計ポイント → 直接対決（公式ルールどおり） |
| 予選リーグ + 決勝トーナメント | 予選はリーグと同じ。上位が決勝トーナメントへ |
| BOT対戦予選 + 決勝トーナメント | 合計ポイント → 一撃 → アイテム。上位が決勝トーナメントへ |

詳しくは [14-1. 大会形式を選ぶ](#14-1-大会形式を選ぶ) を参照してください。

## 14. 大会を運営する

大会データを読み込ませておくと、対戦カードを選ぶだけで両プレイヤーのプログラムが
自動で割り当てられ、結果を確定すると勝ち上がりが進みます。観客席の画面にも
トーナメント表・順位表が出ます。

### 14-1. 大会形式を選ぶ

4つの形式があります。どれを選んでも、当日の操作の流れ (14-3) は同じです。

| 形式 | 進め方 | 向いている場面 |
|---|---|---|
| **トーナメント** | 勝ち上がり。負けたら終わり | 標準。3位決定戦も行える |
| **リーグ** | 全員と1回ずつ戦い、勝ち点で順位を決める | 少人数でじっくり |
| **予選リーグ + 決勝トーナメント** | 予選をいくつかのリーグに分け、各リーグの上位が決勝へ | 人数が多く、総当たりが組めるとき |
| **BOT対戦予選 + 決勝トーナメント** | 全員が運営の同じ BOT と1試合ずつ戦い、獲得ポイントの上位が決勝へ | 人数が多く、総当たりが組めないとき |

予選を持つ2形式では、予選が終わったところで **決勝進出者を運営が確定する** 手順が入ります
(14-4)。予選の順位の付け方と、同点になったときの直し方が形式ごとに違います。

| | 予選リーグ | BOT対戦予選 |
|---|---|---|
| 予選の対戦相手 | 同じリーグの参加者どうし | 全員が同じ運営BOT |
| 予選の試合数 | 各リーグ nC2 | 参加者数と同じ |
| 順位の決め方 | 勝ち点 → 合計ポイント → 直接対決 | 合計ポイント → 一撃ボーナス → アイテムポイント |
| 同点の直し方 | 枠ごとにプルダウンで選び直す | 確認リストから削って人数を合わせる |
| 予選の表 | リーグごとの星取表 + 順位表 | エントリーリスト + 順位リスト |

#### BOT対戦予選について

**運営が用意した1つの BOT を「ものさし」にする**方式です。全参加者がその同じ BOT と
1試合ずつ戦い、獲得ポイントの上位が決勝トーナメントへ勝ち上がります。予選の試合数が
参加者数と同じになるので、エントリーが増えても予選が回ります。

**運営側はプログラムもマップも全参加者に対して同一です。** これが順位の根拠なので、
アプリは大会データの時点で「予選のマップが決まっていること」を必須にしています。

**BOT に勝ったかどうかは順位に影響しません。** 同じものさしで測ったポイントそのもので
並べます。同点は 一撃ボーナス → アイテムポイント の順で比べ
（総取りで拾ったぶんより、自分でアイテムを取ったぶんを上に置きます）、
それでも並んだら同着として運営が決めます。全員が BOT としか戦っていないので、
リーグ戦の「直接対決」にあたる決め手はありません。

### 14-2. 大会データを準備する

3つの方法があります。どれで作っても出来上がるものは同じ (`server/tournament/<大会ID>/`) です。

#### 方法A: 画面で作る (いちばん手軽)

大会運営ウィンドウの「大会」タブで **「+ 新規作成」** を押すと入力フォームが開きます。
JSON を書く必要はありません。

1. **大会名** を入れます。**大会ID** は保存先のフォルダ名で、半角英数字と `. _ -` だけが
   使えます (既定で日付から自動生成されるので、そのままでも構いません)
2. 14-1 の形式を選びます
3. ルールを決めます。**その形式で意味を持つ項目だけが出ます**
   - 全形式 — 2ゲーム制 / 固定マップ / 回戦ごとのマップ
   - トーナメント・予選あり — 3位決定戦
   - リーグ・予選リーグ — 勝ち点 / 2回総当たり
   - 予選リーグ — 予選リーグ数 / 各リーグの進出人数
   - BOT対戦予選 — BOTのプログラム・表示名・予選のマップ・決勝進出人数、
     1ゲーム制のときは参加者の手番 (先攻 / 後攻)
4. 参加者を追加します。**「まとめて追加」** に1行1プレイヤーで貼り付けると一括登録できます。
   **上から順が選手番号**で、番号の小さい方が第1ゲームで先攻になります。`↑` `↓` で入れ替えます
5. 各参加者のプログラムを選びます
   - **未提出（当日割り当て）** — まだ届いていない。当日プログラムライブラリから割り当てます
   - **内蔵CPU** — リハーサル用
   - **ライブラリのプログラム名** — プログラムライブラリに登録済みのものを直接指定

   > **プレイヤー名は、プログラムを選ぶと自動で入ります。**
   > プログラムのソースに名前が書かれていれば（`Client(name='舞鶴A')` の直書き、または
   > `parser.add_argument('-n', '--name', default='舞鶴A')` の既定値）、それが
   > プレイヤー名欄の初期値として入ります。これは対戦画面のスコアバーに出る名前と同じものです。
   > 入ったあとは自由に書き換えられ、**一度書き換えた名前はプログラムを選び直しても
   > 上書きされません**。ソースに名前が書かれていなければ空欄のまま手で入力してください。
6. 組み合わせは既定で**標準シード配置**（第1シードと第2シードが決勝まで当たらない並び）が
   自動生成されます。実行委員会が決めた組み合わせがある場合は **「手動で指定する」** に
   チェックを入れ、1回戦の対戦カードを直接指定してください。空きは bye（不戦勝）になります
   - **予選リーグ** では、参加者は選手番号順に蛇行 (A, B, B, A …) で予選リーグへ
     振り分けられます。人数が割り切れないときは前のリーグが多くなります
     （5人2リーグなら A が3人、B が2人）。各行のプルダウンで個別に変えられ、
     **「自動で振り分け直す」** で元に戻せます
   - **予選を持つ形式では決勝トーナメントの1回戦を手で指定できません。** 顔ぶれが
     予選の順位で決まるためです
7. 下部に「全 N 試合」と表示されるので確認し、**「この内容で作成」** を押します

作った大会は一覧の **「編集」** から直せます。ただし**上書き保存すると進行状態は
最初からやり直しになります**（実施済みの試合があるときは確認が出ます）。
運営中の大会は編集できないので、先に「運営を終了」してください。

編集画面の **「別名で保存」** を押すと、元の大会を残したまま別のIDで複製できます。
去年のデータを土台に今年のものを作る、予選の組み分けだけ変えた案を残しておく、
といった使い方ができます。元の大会の進行状態はそのままです。

**大会ID** は編集中でも書き換えられます。「別名で保存」を使わずにIDを変えると
**その大会の名前（フォルダ名）が変わります**（元のIDは残りません）。同梱した
`programs/` のプログラムも一緒に移るので、参加者のプログラムが外れることはありません。
変更しようとしているIDが他の大会と同じときは保存できません。

> プログラムライブラリから選んだプログラムは `tournament.json` には書き込まれません
> (プログラムの ID はこの PC でしか通じないため)。他の PC へ持っていくときは
> 「方法D: 書き出して持ち出す」を使ってください。

#### 方法B: フォルダに置く (事前準備向け)

```
server/tournament/2026-maizuru/
├── tournament.json
└── programs/
    ├── team_a.py
    └── team_b.py
```

`tournament.json` の書き方:

```jsonc
{
  "name": "第N回 U-15 プログラミングコンテスト",
  // "league" / "group-then-bracket" / "bot-then-bracket" も指定できる
  "format": "single-elimination",

  // 全形式に共通する対戦の条件
  "match": {
    "doubleMode": true          // 先後を入れ替えた2ゲームで1試合 (公式ルール)
  },

  // 形式ごとの進め方。書ける項目は format で決まる
  "stage": {
    "thirdPlaceMatch": true,    // トーナメント・予選あり: 3位決定戦を行う
    "map": {
      "catalogId": null,        // 大会全体の固定マップ (null なら毎回ランダム生成)
      "bracketStages": []       // 決勝トーナメントの回戦ごとのマップ (index=回戦)
    }

    // --- "league" / "group-then-bracket" ---
    // "league": {
    //   "points": { "win": 3, "draw": 1, "loss": 0 },
    //   "doubleRoundRobin": false
    // },

    // --- "group-then-bracket" ---
    // "groupCount": 2,          // 予選リーグの数
    // "advancePerGroup": 2,     // 各リーグから決勝へ上がる人数

    // --- "bot-then-bracket" ---
    // "advanceCount": 8,        // 決勝トーナメントの出場人数 (2以上)
    // "bot": {
    //   "program": { "file": "programs/bot.py" },  // null なら当日割り当て
    //   "name": "運営BOT",                          // 省略時は「運営BOT」
    //   "map": "<マップID>",                        // 予選で全員が使うマップ
    //   "participantSide": 0                        // 参加者の手番 0=先攻 / 1=後攻
    // }
  },

  "participants": [
    { "name": "舞鶴A", "seed": 1, "program": { "file": "programs/team_a.py" } },
    { "name": "舞鶴B", "seed": 2, "program": { "file": "programs/team_b.py" } },
    { "name": "舞鶴C", "seed": 3, "program": null }
  ]
}
```

- **`seed`** は組み合わせ表の選手番号です。第1ゲームでは番号の小さい方が先攻になります。
  省略すると記載順に扱われます。
- **`group`** は予選リーグのときだけ使う「所属する予選リーグ」です (0 = Aリーグ, 1 = Bリーグ …)。
  省略すると選手番号順に蛇行で自動振り分けされるので、普通は書かなくて構いません。
- **`program: null`** は「まだ提出されていない」という意味です。当日プログラムが届いたら
  画面から割り当てられます。
- **`{ "builtin": "cpu" }`** を指定すると内蔵CPUになります。リハーサルに便利です。
- 参加者が2の冪でない場合 (5人・7人など) は、上位シードが自動的に**不戦勝**になります。
- `stage` に他の形式の項目が書いてあっても無視されます。

#### 方法C: 画面から読み込む (当日の追加・差し替え向け)

「大会」タブの **「ファイルを読み込む」** から `.zip` または `.json` を選びます。
`.zip` は `tournament.json` と `programs/` をまとめたもので、フォルダを1階層かぶせた形でも
そのまま読めます。

#### 方法D: 書き出して持ち出す

大会データの一覧で、その大会の **「書き出し」** を押すと `<大会名>_大会データ.zip` が
保存されます。中身は `tournament.json` と `programs/*.py` — つまり**方法C の
「ファイルを読み込む」にそのまま入れられる形**です。

- 会場のPCへ大会をまるごと移す
- 準備した大会を予備機にも入れておく
- 大会データをバックアップする

といった用途に使えます。移動先ではプログラムも一緒に入るので、参加者が
「プログラム未登録」になることはありません。

覚えておくこと:

- **進行状態は入りません。** 読み込んだ先では、何試合か終わっていた大会でも
  最初からのやり直しになります。
- **`.exe` のプログラムは同梱されません。** 対象の参加者がいると書き出しのあとに
  お知らせが出ます。移動先で改めて割り当ててください。
- **マップの指定は移動先では効きません。** マップの ID はその PC のマップライブラリでしか
  通じないためで、「大会の設定に従う」動きになります (元の PC で読み直せば元どおりです)。

### 14-3. 当日の流れ

コントロール画面のフッターで **「大会運営...」** を押すと、大会運営ウィンドウが開きます
(ブラウザでは別タブ)。左に大会の表、右に運営パネルが出ます。

運営パネルはこう並んでいます。

```
┌──────────────────────────┐
│ 大会名                     │
├──────────────────────────┤
│ ▶ 今やること                │  ← いつでも一番上。ここだけ見れば進む
│   第1回戦 第1試合           │
│   舞鶴A × 舞鶴D             │
│   [ この試合を準備 ▶ ]      │
├──────────────────────────┤
│ [ 大会 ] [ 進行 ] [ 設定 ]  │
│  …選んだタブの中身          │
└──────────────────────────┘
```

**「今やること」には、その時に押すべきものが1つだけ出ます。** 探す必要はありません。

| 今やること | 内容 |
|---|---|
| 次の試合を準備する | **「この試合を準備 ▶」** で両者のプログラムを COOL / HOT に自動割り当て |
| ゲームを開始する | コントロール画面の **「ゲームスタート」** を押す (2ゲーム制なら「第2ゲームへ ▶」も) |
| 結果を確定する | 結果ダイアログで内容を確認して **「この結果で確定 ▶」** |
| 決勝進出者を確定する | 予選が終わった。顔ぶれを確認して確定する (14-4) |
| プログラムを割り当てる | 次の試合の出場者が未提出。その場でライブラリから選ぶ |
| 大会終了 | 全試合が終わった。「進行」タブで結果を書き出せます |

タブの中身は次のとおりです。

| タブ | 中身 |
|---|---|
| **大会** | 運営する大会を選ぶ・作る・読み込む・書き出す |
| **進行** | 決勝進出者の確認、試合の一覧と結果の取り消し、結果の書き出し |
| **設定** | 観客席に出す表 / 回戦ごとのマップ / オートプレイ |

大会を選ぶと自動で「進行」タブに移り、運営を終了すると「大会」タブに戻ります。

運営中、観客席の画面 (対戦表示ウィンドウ) は運営の操作に合わせて切り替わります。

| 運営の操作 | 観客席の画面 |
|---|---|
| 「この大会を運営」 | トーナメント表・リーグ表が画面いっぱいに出ます (予選ありなら予選の表) |
| 「この試合を準備」 | 試合準備画面 (対戦カード・マップ・表) |
| 「ゲームスタート」〜対戦中 | 盤面 |
| 対戦終了〜確定まで | ゲームの結果 |
| 「この結果で確定 ▶」 | 表に戻り、**いま終わった試合が強調表示**されます |
| 最後の試合を確定 | 表彰画面 |

表彰画面には大会名と優勝 (トーナメントは準優勝・3位決定戦を行った場合は第3位、
リーグは上位3位) を大きく出し、その下に最終のトーナメント表・順位表が残ります。
予選ありの大会では決勝トーナメントの結果から表彰台を作り、
**表に出るのも決勝トーナメントだけ**です（予選の結果を見せたいときは 14-7 で切り替えます）。
表彰式のあいだ出したままにできます。

**3位決定戦は決勝より先に案内されます。** 準決勝が両方終わると決勝と3位決定戦が同時に
実施可能になりますが、「今やること」には**3位決定戦が先に**出ます
(決勝を大会の締めくくりにするため)。トーナメント表では決勝が上、3位決定戦がその下に
表示されます — 実施順と表示順は別物です。
順番を入れ替えたいときは、トーナメント表で決勝のカードを直接選んで
「この試合を準備」を押してください。

> この流れをアプリに任せて、大会を自動で進めることもできます (14-8 オートプレイ)。

### 14-4. 決勝進出者を確定する（予選のある形式）

予選が全部終わると、「今やること」が **「決勝進出者を確定する」** になり、
観客席の画面が予選の最終結果になります。

**確定するまで観客席は予選の最終結果を出したままです**（時間では切り替わりません）。
観客が順位を確かめる時間になり、運営が同点の枠を見直す時間にもなります。
**確定するまで決勝トーナメントの試合は準備できません。**
押し間違えたら「確定を取り消す」で戻せます。予選の試合をやり直したときも
確定は自動で外れるので、もう一度確定し直してください。

「進行」タブの **「決勝進出者」** で顔ぶれを確認します。直し方は形式で違います。

#### 予選リーグ — 枠ごとに選び直す

順位は公式ルールどおり **勝ち点 → 全試合の合計ポイント → 直接対決** で決まります。
そこまで並んで順位が決まらない場合も**枠は自動で埋まる**ので決勝トーナメントは
始められますが、パネルに印が出ます。

| 表示 | 意味 |
|---|---|
| 自動 | 順位どおりに決まりました |
| 同着 | 同じ順位が複数いますが、どちらも上がるので選び直す必要はありません |
| **同点 — 要確認** | **上がる人と上がらない人が並んでいます。運営で決めてください** |
| 手動で変更 | 運営が選び直した枠です |
| 予選の結果待ち | 予選がまだ終わっていません |

差し替えるには、**「決勝進出者」の枠のプルダウンから選ぶ**か、
**トーナメント表の1回戦のカードを選んで**、下に出るプルダウンから選びます。どちらでも同じです。
「自動」に戻せば順位どおりに戻ります。

- 選べるのは**そのリーグの参加者**だけです
- 同じプレイヤーを2つの枠に入れることはできません
- その枠を使う試合が準備中・対戦中のときは変更できません。先にリセットしてください
- すでに実施済みの試合の枠を変えると、**その結果は取り消されます**（確認が出ます）

#### BOT対戦予選 — 確認リストから削る

確認リストには、上位の進出人数ぶんに加えて、**通過ラインで同点になった人が全員載ります**。
定員より多いときは「あと ◯ 名を削ってください」と出て、**確定ボタンが押せません**。

- 各行の **✕** でその人を候補から外します。外すと下の順位が繰り上がります
- 外した人の行は取り消し線つきで残るので、**「戻す」** でいつでも戻せます
- 同点で並んだ行には **「同点」** の印が付きます
- 定員ちょうどになると確定ボタンが押せるようになります

順位リストの列は次のとおりです。

| 列 | 意味 |
|---|---|
| 結果 | ○ BOTに勝ち / △ 引き分け / ● 負け。**順位には影響しません** |
| ポイント | 獲得アイテム数×10 ＋ 一撃ボーナス ＋ 総取りボーナス（13-2 の「ポイント」） |
| 一撃 | ポイントの内訳のうち一撃ボーナス |
| アイテム | ポイントの内訳のうちアイテムぶん |

> 同点でなくても削除できます（当日欠席になったプレイヤーを外す、など）。
> すでに決勝トーナメントの試合を実施していた場合は、**その結果が取り消される**確認が出ます。

**予選のマップは1試合でも実施したあとは変更できません。** 途中で変えると参加者ごとに
条件が変わり、ポイントで順位を付ける前提が崩れるためです。どうしても変えたいときは
予選をやり直してください。

### 14-5. 同点になったとき

競技ルールでは「勝利数も合計ポイントも同じ場合は、マップを変更して再試合」と定められています。
**勝ち上がりの試合**で同点になると確定ボタンが押せなくなり、代わりに3つの選択肢が出ます。
（リーグ戦と予選リーグの試合では引き分けは正当な結果なので、そのまま確定できます。勝ち点1が付きます。）

| 選択肢 | 使いどころ |
|---|---|
| ① マップを変更して再試合 | 公式ルールどおりの既定の対応 |
| ② 審判裁定で勝者を指定 | 抽選・じゃんけんなどで決めた場合。理由を残せます |
| ③ 両者敗退にする | どちらも次に進めない場合 |

固定マップを使っている場合、①では**別のマップを選ばないと再試合を開始できません**
(同じマップのまま再試合するとルール違反になるため)。回戦ごとのマップを指定している
場合も同じです。

### 14-6. やり直したいとき

- **結果を取り消したい**: 「進行」タブの試合一覧で **「取り消す」**。その試合より後の
  結果も一緒に巻き戻ります (確認を求められます)
- **対戦をやり直したい**: 結果ダイアログの「やり直す」
- **大会を最初から**: `server/tournament/<大会id>/state.json` を削除するか、
  「大会」タブで編集して上書き保存します
- **予選の結果を取り消したい**: 予選の試合を取り消すと、順位が変わって決勝トーナメントの
  顔ぶれも変わりうるため、**決勝トーナメントの結果もすべて巻き戻ります**。確認が出ます

### 14-7. 観客席に出す表を切り替える（予選のある形式）

**運営画面**: 表の左上の **「予選」「決勝トーナメント」** でいつでも切り替えられます。

**観客席の画面**: 「設定」タブの **「観客席に出す表」** で決めます。

| ボタン | 出るもの |
|---|---|
| 進行に合わせる | 予選中は予選の表、決勝進出者を確定すると決勝表。全部終われば表彰画面 |
| 予選リーグ表 / BOT対戦予選の表 | いつでも予選の表 |
| 決勝トーナメント表 | いつでも決勝トーナメント表。全部終わっていれば順位付きの表彰画面 |

**この切り替えは運営画面の表示とは連動しません。** 観客には予選表を出したまま、
手元では決勝の組み合わせを確認する、といった使い方ができます。
対戦中は観客席には盤面が出ます（表は試合の合間に出ます）。

### 14-8. オートプレイ（自動で大会を進める）

「設定」タブの **「オートプレイ」** で **「自動で進める ▶」** を押すと、14-3 の操作を
アプリが代わりに行い、大会を最後まで進めます。無人の展示や、当日の流れを通しで
確認するリハーサルに使ってください。

**画面が切り替わるたびに数秒ずつ間が空きます。** 観客が対戦カードと結果を目で
追えるようにするためで、待ち時間はおおよそ次のとおりです。

| 場面 | 待ち時間 |
|---|---|
| 直前の試合の結果を表で見せる → 次の試合を準備 | 約6秒 |
| これから戦う2人とマップを見せる → ゲームスタート | 約5秒 |
| 第1ゲームの結果を見せる → 第2ゲームへ | 約6秒 |
| 対戦の最終結果を見せる → 結果を確定 | 約8秒 |
| 予選の最終順位を見せる → 決勝進出者を確定 | 約12秒 |
| 表彰画面を見せる → 最初からやり直す（デモモード） | 約20秒 |

**デモモード（繰り返す）** を一緒に押しておくと、全試合が終わって表彰画面を出したあと、
**同じ大会データで進行を最初からやり直して繰り返します**。結果は消えるので、
本番の運営では切っておいてください（回戦ごとのマップの指定と、プログラムの
割り当ては消えません）。

自動進行が止まるのは次の場合です。理由がパネルに表示されます。

| 止まる場面 | 表示 | 対応 |
|---|---|---|
| 全試合が終わった（デモモードでないとき） | 全ての試合が終了しました | そのまま表彰画面が残ります |
| 勝ち上がりの試合が同点になった | 「〜」が同点です… | 14-5 のとおり運営が決めてから、もう一度「自動で進める ▶」 |
| プログラムが登録されていない参加者に当たった | 〜のプログラムが登録されていません | プログラムを割り当ててから再開してください |

**同点の裁定や再試合を自動では行いません。** 競技ルールでは運営が決めることなので、
そこでは必ず止まって指示を待ちます。

> **決勝進出者の確定だけは、同点のボーダーが残っていても自動で通します。**
> 自動判定は必ず順位どおりに枠を埋めるので大会は完走しますが、同点を人が決めたい
> 本番では、予選が終わったところで自動進行を切ってください。

自動進行の途中でも、手動の操作（「この試合を準備」やフッターの「ゲームスタート」）は
そのまま使えます。手で進めたぶんは自動進行がそのまま引き継ぎます。
止めたいときは **「自動進行を止める」** を押してください。

### 14-9. 結果を書き出す

「進行」タブの **「結果の書き出し」** から書き出せます。

| ボタン | 内容 |
|---|---|
| JSON | 定義・全試合・順位をまとめたもの (記録用) |
| 試合CSV | 1行1試合。「区分」列で予選A / 予選B / 決勝T を見分けられます |
| 順位CSV | リーグ・予選ありのときのみ。勝ち点・合計ポイント付きの順位表 (予選はリーグごとに出ます) |

CSV は Excel でそのまま開けます (UTF-8 の BOM 付き)。

### 14-10. 注意点

- 大会運営中は**セットアップ画面のデモモードとリピートモードが自動的に切れます**。
  ライブラリからランダムに選んで勝手に対戦を始めてしまうためです。大会を自動で進めたいときは
  14-8 のオートプレイを使ってください（こちらは大会データどおりの組み合わせで進みます）
- 大会データは 1つの部屋でだけ運営できます。同じ大会を2つの部屋で同時に進めることはできません
- 大会用に取り込んだプログラムは、デモモードのランダム抽選には出てきません
