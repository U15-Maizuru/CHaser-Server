# 開発ワークフロー

**このファイルは経緯を残す。** 「なぜこの手順なのか」は過去に踏んだ罠が理由であることが多く、
理由を消すと同じ罠にまた掛かる。ドキュメント (`docs/`) は初版として書く方針なので、
そこには書けない類の知識をここに置く。

## 起動

```bash
pnpm dev     # Electron + Vite + Backend が同時に立つ
```

対戦表示ウィンドウ (1280×800) とコントロールウィンドウ (1280×800) が開く。
大会運営ウィンドウはコントロール画面のフッター「大会運営...」から開く。

`@u15/ws-types` を変えたときは先に `pnpm --filter @u15/ws-types build`。
他パッケージは `dist/` を参照するので、ビルドしないと型が古いままになる。

## E2E

```bash
pnpm test:e2e       # backend/electron の dist が要るので build を前置してある
```

Vite の起動は `apps/electron/viteLauncher.cjs` を dev と共有している。
pnpm 経由 (`shell: true`) で起動すると cmd → pnpm → cmd → vite と実体が3階層下に来て、
後始末で木ごと落とすときに追いきれなくなるため、CLI を直接叩いている。

スクリーンショットは `test-screenshots/` に出る。

### 起動前に 5173 / 8765 を掴むプロセスを落とすこと

**残留した node が前回のゴーストのまま生きていると、E2E がそれに繋がって謎の失敗をする。**
Vite は「既に起動中」と判断してスキップし、バックエンドは古いビルドのまま動くので、
直したはずの挙動が直っていないように見える。

`dev` と E2E の終了処理は `apps/electron/src/killTree.ts` で子プロセスを木ごと落とすように
してあるが、強制終了したあとは残ることがある。疑わしいときは:

```bash
netstat -ano | grep -E ":5173|:8765"
```

で掴んでいる PID を確認して落とす。

### E2E は文言ではなく `data-testid` / `data-*` で掴む

ボタンのテキストで探すヘルパ (`clickText`) は便利だが、UI の言い回しを変えると壊れる。
運営パネルの「今やること」は `[data-testid="next-action"]` の `data-action`
(`arm` / `start` / `confirm` / …) を読む (`nextActionKind`)。
新しく状態依存の分岐を足すときは、同じように機械可読な印を付ける。

運営パネルはタブ構成なので、一覧や設定を操作する前に `openPanelTab(tw, '大会')` で
タブを切り替える必要がある。大会を選ぶと自動で「進行」タブへ移る。

## 見た目の検証

**テストとビルドが通っただけでは、見た目の欠陥は素通りする。**
canvas 描画 (盤面・マップエディタ) とレイアウトの変更は、必ず実際に動かして
スクリーンショットを見ること。E2E が各画面を撮るので、`pnpm test:e2e` のあと
`test-screenshots/` を開くのがいちばん早い。

見ておく画面:

| ファイル | 画面 |
|---|---|
| `01_setup_ui.png` | セットアップ (COOL / マップ / HOT の3カラム) |
| `04_game_playing.png` | 対戦中の盤面 |
| `tournament-bracket.png` | 大会運営ウィンドウ (表 + パネル) |

### 過去に画面で起きたこと

- **セットアップ画面が振動する**: マッププレビューを大きくする → 行が縦にあふれて
  スクロールバーが出る → 行の内幅が縮む → プレビューが小さくなる → スクロールバーが消える、
  の循環。`StartupDialog` の `scrollbarGutter: 'stable'` で止めている。
  「測定 → 反映 → 再測定」の形を書くときは、測る対象が反映結果に依存しないことを確かめる。
- **flex の子が中身の幅で押し広げられる**: `min-width: auto` が既定なので、
  幅を閉じ込めたい箱には `minWidth: 0` を明示する。
- **待機画面のマップだけ向きが違う**: 第2ゲームは盤面を180°反転する
  (`doubleMode && currentRound === 1`)。プレビューにも同じ条件で `flip` を渡さないと、
  ゲームが始まった瞬間に向きが変わって見える。
